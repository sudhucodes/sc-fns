## Import Strategies

`sc-fns` supports two flexible import patterns:

### 1. Subpath Imports (Recommended for Frontend Bundles)

Subpath imports allow bundlers (Vite, webpack, Rollup, Turbopack, esbuild) to only load the specific file for that namespace. This guarantees minimum bundle footprint and lightning-fast build resolution.

```ts
import { slugify, capitalizeWords } from "sc-fns/string";
import { generateUUID, generateOTP } from "sc-fns/id";
import { chunkArray, shuffleArray } from "sc-fns/array";
import { clamp, formatNumber } from "sc-fns/number";
import { pick, omit } from "sc-fns/object";
import { formatDate, formatRelativeTime } from "sc-fns/date";
import { isEmail, isURL } from "sc-fns/validation";
import { buildURL } from "sc-fns/url";
import { debounce, retry } from "sc-fns/common";
import { formatFileSize } from "sc-fns/file";
import { copyToClipboard } from "sc-fns/browser";
```

### 2. Root Import (Convenient for Backend / Full-Stack)

You can also import any utility directly from the root package `"sc-fns"`. Because all functions are marked as side-effect free, modern bundlers will automatically tree-shake unused exports in production builds:

```ts
import { slugify, generateUUID, chunkArray, clamp, formatDate, isEmail } from "sc-fns";
```

## Immutability Guarantee

All functions in `sc-fns` follow functional, non-mutating principles. Calling functions like `shuffleArray()`, `chunkArray()`, or `omit()` will **never** modify the original data passed in:

```ts
const original = [1, 2, 3];
const shuffled = shuffleArray(original);

console.log(original); // [1, 2, 3] (Untouched!)
```
